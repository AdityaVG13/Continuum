Continuum

Three ways to choose. One gate. The model patches into the sim dispatch. The router and the leap patch in beside it, not through it.

Where the model enters

  • • The participant loop is the only path that asks Meta to choose.
  • • It is given the observation, the task, and the catalogue. The context does not name an action.
  • • A live call runs only when MODEL_API_KEY is set. A recorded reply uses the same dispatch.
  • • Abstain, the round cap, or a rejected tool leaves the path alone. The loop does not substitute sqm-fair.

What patches in

  • • Sim, lease store, and the router transport sit behind the actuator. The router verb does not pass the guardian.
  • • Meta patches in under the participant: prompt, six-tool schema, shape, provider, curl. The key never enters the prompt.
  • • The leap patches in at the native ABI: ASUS web, macOS host, vault refs. It is a different entry point.
  • • contracts.goose is the shared record. A new backend implements the same apply, restore, and readback. It does not invent a field.

What is not connected

  • • The model does not drive the router. --loop with a key decides on the sim. The router leg is still the scripted actuator proof.
  • • run_meta_task is a stub. The task the controller reads is a labelled case, not a live workload model.
  • • SSH and tc are named in the access enum and not built. The lab path is the WebApi double.
  • • A tool call is not an applied profile. An applied profile is not a recovered task. Those stay separate records.
