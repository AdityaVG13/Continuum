# Optimization workflow

The owner wants the whole flow optimized, not indiscriminate service removal.
Map task -> host -> interface/Wi-Fi -> router -> upstream -> destination/provider.
Separate observed architecture from guesses and note the actual controllable leg.

Profile first. Use host observations and protected runtime inventory; name units,
window, resource costs and missing data. Counter changes are not automatically
bufferbloat. Diagnose the dominant measured cost before choosing one reversible
intervention. Preserve owner-required services, security and management access.

Use the existing bounded primitive for a justified experiment, verify its actual
readback and recovery, then measure end-to-end outcome against its baseline. A
retained successful setting is not proof of better latency, useful goodput or task
completion. Restore owned changes when ineffective; do not overwrite another
operator's intervening configuration.

Develop low-maintenance redundancy and reusable profiling only when the observed
architecture needs it. That design is your task with the owner, not a built-in
recipe. Do not add permanent workers, packages, probes or timers speculatively.
Keep concise architecture knowledge and remaining questions in the device note.
Router/device reboots, resets, firmware changes and destructive work stay outside
standing permission. Internal service restarts may use supported capabilities.
